# Tasks Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a standalone `/tasks` page to the daily-brief-v2 webapp showing every open Asana task relevant to the signed-in user, grouped by due date, with the ability to check a task off to mark it complete directly in Asana.

**Architecture:** Reuses existing machinery end to end rather than adding a parallel implementation: `_fetch_live_action_items` for the Asana pull, `_sync_asana_completed` for the completion write-back, and (newly extracted) `group_action_items` for due-date bucketing — the same server-side-render-a-fragment pattern the brief's Action Items section already uses (`{html, count}` JSON, injected client-side), not the client-side-JS-table pattern `customers.html` uses. A new standalone page (`templates/tasks.html`, styled like `customers.html`) is reached via a new topbar button in `daily-brief-viewer.html`.

**Tech Stack:** Flask, Jinja2 templates, vanilla JS (no framework), pytest (hand-rolled fakes, no mocking library).

## Global Constraints

- No `Co-Authored-By`/attribution changes beyond what's already in this repo's commit convention.
- Every route in this app today has **zero automated tests** — the test suite (`tests/`) deliberately never imports `app.py`, because doing so requires live env vars (`FLASK_SECRET_KEY`, `AZURE_TENANT_ID`, etc.) and a real `psycopg2`/Postgres connection (see `tests/template_test_utils.py`'s docstring). Only pure, dependency-free logic gets automated tests (e.g. `asana_discovery.find_new_projects`, injected `fetch_fn`, no network, no mocking library). This plan follows that convention exactly: new pure logic gets real tests; new Flask routes get manual verification instructions instead of a fabricated test harness. This is a deliberate deviation from the approved spec's testing bullets about `GET /tasks` and `GET /api/tasks` — flagged here rather than silently skipped.
- Deviation from the approved spec, found while reading the code: the spec described `GET /api/tasks` returning a raw JSON item list with **client-side** JS bucketing (`customers.html`'s pattern), and a new `_bucket_tasks_by_due_date` pure function. Instead, this plan reuses the app's *other* existing pattern — server-side grouping (`_group_action_items`) + a rendered HTML fragment returned as `{html, count}` — because that function already implements almost exactly this bucketing (it's what currently powers the brief's Action Items section) and is a closer match to "due-date logic thats in the current app" than writing a second, parallel implementation. This does add one new bucket ("Due Today") to that shared function, which also changes what the *existing* brief page shows (previously: today's and this-week's due items were both lumped into "Due Next 7 Days"; now today's items get their own bucket there too) — a small, low-risk, backward-compatible addition (empty buckets are already omitted by both existing templates that consume it), but a real behavior change to an already-shipped feature, so it's called out explicitly rather than snuck in.
- Windows/PowerShell environment — commands below use `venv\Scripts\python`/`venv\Scripts\pytest` per this repo's own `DEPLOYMENT.md` "Local development" section, not Unix `venv/bin/...`.
- Bucket label wording: the spec called the third bucket "Due this week"; this plan keeps the existing app's established label "Due Next 7 Days" for that same bucket (`due-soon`) instead of introducing a second wording for the same concept across the brief and Tasks pages.

Create `viewer/webapp/action_items.py`:

```python
"""Groups the Action Items list (brief-file items + live Asana pulls) into
the fixed due-date-based subsections used by the brief's Action Items
section and the standalone Tasks page. Pure logic — no Flask, no DB, no
network — so it's importable in tests without app.py's env-var
requirements (FLASK_SECRET_KEY, AZURE_TENANT_ID, etc.) or a live Postgres
connection. Moved out of app.py verbatim; see app.py's git history before
this change for the original inline version."""
from datetime import date, timedelta

# Fixed order and labels for the Action Items subsections. "New Items"
# always renders first regardless of due date so a freshly created task
# doesn't get buried under overdue items from prior days.
ACTION_SUBSECTIONS = [
    {'slug': 'new', 'label': 'New Items'},
    {'slug': 'overdue', 'label': 'Overdue'},
    {'slug': 'due-soon', 'label': 'Due Next 7 Days'},
    {'slug': 'no-due-date', 'label': 'No Due Date'},
]


def group_action_items(items, today_iso: str):
    """
    Splits the flat Action Items list into the fixed subsections the
    template renders. Membership is exclusive — an item lands in exactly
    one group, checked in this priority order:

      1. is_new  — content.is_new is true (this brief run created the
         Asana task itself; see references/item-sync.md). Takes priority
         over the date-based groups below so a brand-new overdue-looking
         task still shows up under "New Items", not "Overdue".
      2. overdue — content.due_on is set and before today.
      3. due-soon — content.due_on is set and within the next 7 days
         (inclusive of today).
      4. no-due-date — everything else: no due_on at all, or a non-Asana
         action item with no natural date.

    Items are sorted by due_on ascending within groups 2 and 3; group 4
    keeps upstream display_order (already priority-ordered by the skill)
    since there's no date to sort on, and group 1 does the same.
    Returns a list of {slug, label, items} dicts, omitting empty groups —
    the template skips rendering a subsection header with nothing under it.
    """
    today = date.fromisoformat(today_iso)
    week_out = today + timedelta(days=7)
    buckets = {s['slug']: [] for s in ACTION_SUBSECTIONS}

    for item in items:
        content = item.get('content') or {}
        due_on = content.get('due_on')
        if content.get('is_new'):
            buckets['new'].append(item)
            continue
        if due_on:
            try:
                due_date = date.fromisoformat(due_on)
            except ValueError:
                due_date = None
        else:
            due_date = None
        if due_date is not None and due_date < today:
            buckets['overdue'].append(item)
        elif due_date is not None and due_date <= week_out:
            buckets['due-soon'].append(item)
        else:
            buckets['no-due-date'].append(item)

    for slug in ('overdue', 'due-soon'):
        buckets[slug].sort(key=lambda it: (it.get('content') or {}).get('due_on') or '')

    groups = [
        {**s, 'items': buckets[s['slug']]}
        for s in ACTION_SUBSECTIONS
        if buckets[s['slug']]
    ]

    # Every subsection is further split by board (Asana project name) so
    # items are visually grouped by account rather than rendering as one
    # undifferentiated list. "My Tasks" (content.project_name is null,
    # meaning no configured project GID for that account, or a non-Asana
    # action item) sorts last since it's the catch-all. Item order within
    # each board is preserved from the incoming list (display_order for
    # New-Item-shaped rows, due_on sort for date-bucketed rows, upstream
    # ordering for live-pulled ones).
    for group in groups:
        boards = {}
        for item in group['items']:
            board_name = (item.get('content') or {}).get('project_name') or 'My Tasks'
            boards.setdefault(board_name, []).append(item)
        group['boards'] = [
            {'name': name, 'items': boards[name]}
            for name in sorted(boards, key=lambda n: (n == 'My Tasks', n))
        ]

    return groups
```

```python
@login_required
def tasks_page():
    return render_template('tasks.html', user_email=request.brief_user['email'])


@app.route('/api/tasks')
@login_required
def api_tasks():
    """Standalone, cross-day view of every open Asana task relevant to the

        return jsonify({'html': html, 'count': 0, 'needs_pat': True})

    google_token = db.get_google_refresh_token(request.brief_user['id'])
    folder_id = db.get_google_drive_folder_id(request.brief_user['id'])
    account_projects = (
        gdrive_briefs.get_account_projects(google_token, folder_id)
        if google_token

    live_items = _fetch_live_action_items(asana_pat, account_projects, set())
    today_iso = date.today().isoformat()
    action_subsections = group_action_items(live_items, today_iso)
    total_count = sum(len(g['items']) for g in action_subsections)

    html = render_template('tasks_fragment.html', action_subsections=action_subsections, asana_pat_configured=True)
    return jsonify({'html': html, 'count': total_count})
```

```python
@app.route('/api/tasks/<item_key>/checked', methods=['PATCH'])
@login_required
def set_task_checked(item_key):
    """Marks an open task complete/incomplete directly in Asana. Unlike
    /api/items/<section>/<item_key>/checked, there's no Postgres row
    backing this up — these items are never persisted (see
    api_tasks/_fetch_live_action_items) — so a failed Asana write has
    nothing else to fall back on; the client surfaces asana_synced=false
    as an error rather than treating the checkbox as settled."""
    body = request.get_json(silent=True) or {}
    if 'checked' not in body:
        abort(400, 'checked (bool) is required')
    checked = bool(body['checked'])
    pat = db.get_asana_pat(request.brief_user['id'])
    attempted, ok = _sync_asana_completed(pat, item_key, checked)
    if not attempted:
        abort(404)
    return jsonify({'status': 'ok', 'asana_synced': ok})
```

```html
<script>
const BASE = document.querySelector('base')?.href || '';

async function load() {
  const body = document.getElementById('tasks-body');
  try {
    const r = await fetch(`${BASE}api/tasks`, {credentials:'include'});
    if (!r.ok) throw new Error(r.statusText);
    const data = await r.json();
    body.innerHTML = data.html || '<div class="empty">Nothing open — you\'re all caught up.</div>';
    wireCheckboxes();
  } catch(e) {
    body.innerHTML = `<div class="empty" style="color:var(--bad-t)">Failed to load: ${e.message}</div>`;
  }
}

function wireCheckboxes() {
  document.querySelectorAll('.task-check').forEach(cb => {
    cb.addEventListener('change', onCheck);
  });
}

async function onCheck(e) {
  const checkbox = e.target;
  const row = checkbox.closest('.task-row');
  const itemKey = row.dataset.itemKey;
  const checked = checkbox.checked;

  // Optimistic: remove immediately rather than waiting for a full refetch,
  // per the Tasks tab design spec's "Marking complete" section.
  row.classList.add('removing');
  checkbox.disabled = true;

  try {
    const r = await fetch(`${BASE}api/tasks/${encodeURIComponent(itemKey)}/checked`, {
      method: 'PATCH', credentials: 'include',
      headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({checked}),
    });
    if (!r.ok) throw new Error(r.statusText);
    const data = await r.json();
    if (!data.asana_synced) throw new Error('Asana sync failed');
    setTimeout(() => row.remove(), 200);
  } catch(err) {
    row.classList.remove('removing');
    checkbox.disabled = false;
    checkbox.checked = !checked;
    showToast("Couldn't sync to Asana — try again", 'err', 5000);
  }
}

function showToast(text, type, duration) {
  const container = document.getElementById('toast-container');
  const el = document.createElement('div');
  el.className = 'toast ' + type;
  el.textContent = text;
  container.appendChild(el);
  setTimeout(() => {
    el.classList.add('out');
    el.addEventListener('animationend', () => el.remove());
  }, duration);
}

load();
</script>
```
